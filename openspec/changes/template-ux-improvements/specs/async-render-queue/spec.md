# 异步渲染队列规范

## 新增需求

### 需求:渲染任务依赖 AI 任务
系统必须确保图片渲染任务在 AI 任务完成后才开始执行。

#### 场景:自动生成流程中的依赖
- **当** 触发自动生成（AI + 渲染）
- **那么** 渲染任务必须等待 AI 摘要生成完成后再开始

#### 场景:手动重新渲染时检查 AI 完成
- **当** 用户点击"重新生成图片"
- **那么** 系统必须先检查 AI 摘要是否已生成，未生成则等待或提示用户

---

### 需求:任务依赖关系管理
系统必须支持任务之间的依赖关系定义和检查。

#### 场景:定义渲染依赖 AI
- **当** 添加渲染任务到队列
- **那么** 系统必须记录该任务依赖对应的 AI 任务

#### 场景:检查依赖任务状态
- **当** 渲染任务准备执行
- **那么** 系统必须检查所有依赖任务的状态

#### 场景:依赖任务未完成时等待
- **当** 渲染任务的依赖任务状态为 PENDING 或 PROCESSING
- **那么** 渲染任务必须保持 PENDING 状态，不开始执行

---

### 需求:条件触发渲染任务
系统必须在 AI 任务完成后自动触发渲染任务。

#### 场景:AI 摘要完成触发渲染
- **当** AI 生成 social_media_summary 或 detailed_summary 完成
- **那么** 系统必须自动触发所有模板的渲染任务

#### 场景:多个 AI 任务完成触发一次渲染
- **当** social_media_summary 和 detailed_summary 都完成
- **那么** 系统必须触发一次渲染任务（不是两次）

---

### 需求:任务状态监控
系统必须提供任务状态查询和监控功能。

#### 场景:查询渲染任务依赖状态
- **当** 前端轮询渲染任务状态
- **那么** API 必须返回依赖任务的状态信息

#### 场景:显示等待依赖状态
- **当** 渲染任务因依赖未完成而等待
- **那么** 状态必须显示为"等待 AI 生成完成"

---

### 需求:错误处理和重试
系统必须处理依赖任务失败的情况。

#### 场景:AI 任务失败时
- **当** AI 生成任务失败
- **那么** 系统必须标记渲染任务为 FAILED 或跳过渲染

#### 场景:渲染任务超时
- **当** 渲染任务等待依赖超过 5 分钟
- **那么** 系统必须标记任务为 FAILED 并记录日志

---

### 需求:向后兼容
系统必须保持向后兼容，不影响现有功能。

#### 场景:旧 API 不检查依赖
- **当** 使用旧 API 直接触发渲染
- **那么** 系统必须立即执行渲染，不检查依赖

#### 场景:重新生成功能正常
- **当** 用户点击"重新生成"按钮
- **那么** 功能必须按原逻辑工作，不受依赖机制影响
