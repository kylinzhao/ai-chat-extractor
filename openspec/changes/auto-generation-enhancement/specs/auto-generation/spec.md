# Spec: 自动生成

此规范定义对话采集后自动触发生成的行为。

## 新增需求

### 需求: 自动触发生成任务
系统必须在对话采集成功后自动触发所有生成任务，无需用户手动操作。

#### 场景: 采集成功后自动触发生成
- **当** 浏览器插件通过 POST /api/conversations 成功提交新对话
- **那么** 系统必须自动创建并提交以下生成任务：
  - AI 社交媒体摘要生成任务（类型：social_media_summary）
  - AI 详细汇总生成任务（类型：detailed_summary）
  - Bento UI 图片渲染任务（模板：bento）

#### 场景: 采集接口响应不受影响
- **当** 采集接口触发生成任务
- **那么** 采集接口必须在 500ms 内返回成功响应
- **并且** 响应必须包含对话 ID 和基本信息
- **并且** 生成任务必须在后台异步执行

### 需求: 异步任务执行
生成任务必须异步执行，不阻塞采集接口的响应。

#### 场景: 生成任务失败不影响采集
- **当** 生成任务执行过程中发生错误
- **那么** 采集接口必须已成功返回
- **并且** 生成任务的失败必须记录在任务状态中
- **并且** 对话数据必须已保存到数据库

#### 场景: 并发生成任务
- **当** 系统触发生成任务
- **那么** 所有生成任务（AI 摘要、AI 汇总、图片渲染）必须可以并发执行
- **并且** AI 任务并发数不得超过 3 个
- **并且** 渲染任务并发数不得超过 2 个

### 需求: 任务状态持久化
系统必须持久化所有生成任务的状态，供前端查询。

#### 场景: 查询生成状态
- **当** 前端调用 GET /api/conversations/:id/status
- **那么** 系统必须返回该对话的所有生成任务状态
- **并且** 每个任务必须包含：任务类型、状态（pending/processing/completed/failed）、创建时间、完成时间、错误信息（如果失败）

#### 场景: 任务完成后的数据
- **当** 生成任务状态为 completed
- **那么** 生成的结果必须已保存到数据库的对应字段
- **并且** social_media_summary 必须保存到 conversations.social_media_summary
- **并且** detailed_summary 必须保存到 conversations.detailed_summary
- **并且** 图片 URL 必须保存到 conversations.image_urls 数组
