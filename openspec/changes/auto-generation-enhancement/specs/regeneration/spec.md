# Spec: 重新生成

此规范定义用户如何重新生成已有的内容。

## 新增需求

### 需求: 重新生成能力
系统必须允许用户重新生成已存在的内容，以更新过期的数据或改进质量。

#### 场景: 重新生成 AI 摘要
- **当** 用户点击"重新生成社媒摘要"按钮
- **那么** 系统必须创建新的 social_media_summary 生成任务
- **并且** 新任务完成后必须覆盖数据库中的旧数据
- **并且** 界面必须立即显示"生成中..."状态

#### 场景: 重新生成 AI 汇总
- **当** 用户点击"重新生成详细汇总"按钮
- **那么** 系统必须创建新的 detailed_summary 生成任务
- **并且** 新任务完成后必须覆盖数据库中的旧数据
- **并且** 界面必须立即显示"生成中..."状态

#### 场景: 重新生成图片
- **当** 用户点击任意模板的渲染按钮（Bento UI、Newsletter 或 Retro Letter）
- **那么** 系统必须创建新的渲染任务
- **并且** 新任务完成后必须将图片 URL 添加到 image_urls 数组
- **并且** 旧图片必须保留在数组中（不删除历史图片）

### 需求: 重新生成的状态管理
系统必须正确管理重新生成过程中的状态。

#### 场景: 重新生成进行中
- **当** 用户点击重新生成按钮
- **并且** 该类型的生成任务正在进行中
- **那么** 系统必须禁止重复点击
- **并且** 按钮必须显示"生成中..."并禁用
- **并且** 必须显示进度提示

#### 场景: 重新生成完成后的更新
- **当** 重新生成任务完成
- **那么** 系统必须自动更新界面的对应内容
- **并且** 按钮状态必须恢复为可用
- **并且** 必须显示"生成完成"提示（持续 3 秒）
- **并且** 对于图片渲染，新图片必须添加到图片展示区域的最前面

#### 场景: 重新生成失败
- **当** 重新生成任务失败
- **那么** 系统必须保留旧数据不变
- **并且** 必须显示错误信息和失败原因
- **并且** 必须提供"重试"按钮
- **并且** 按钮状态必须恢复为可用

### 需求: 数据覆盖策略
系统必须明确定义重新生成后的数据处理策略。

#### 场景: AI 内容覆盖
- **当** 重新生成 AI 摘要或汇总
- **那么** 新内容必须完全替换数据库中的旧内容
- **并且** 旧内容必须不可恢复（不保留历史版本）
- **并且** 更新时间戳（updated_at）必须更新为当前时间

#### 场景: 图片追加策略
- **当** 重新生成图片
- **那么** 新图片 URL 必须追加到 image_urls 数组
- **并且** 旧图片 URL 必须保留在数组中
- **并且** image_urls 数组必须按添加时间排序

#### 场景: 图片去重
- **当** 重新生成相同模板的图片
- **并且** 该模板的最新图片是在 5 分钟内生成的
- **那么** 系统可以选择：
  - 用新图片替换旧图片（删除旧 URL，添加新 URL）
  - 或者保留两张图片（追加到数组）
- **并且** 系统必须采用一致策略（建议：保留历史）

### 需求: 批量重新生成
系统必须支持批量重新生成多个内容。

#### 场景: 全部重新生成
- **当** 用户点击"全部重新生成"按钮
- **那么** 系统必须依次触发所有类型的生成任务
- **并且** 任务必须按以下顺序执行：AI 摘要 → AI 汇总 → 图片渲染
- **并且** 必须显示整体进度（例如："2/3 完成"）

#### 场景: 批量生成中的状态
- **当** 批量重新生成进行中
- **那么** 系统必须禁用所有单独的生成按钮
- **并且** 必须显示"批量生成中..."提示
- **并且** 必须允许用户取消批量生成
