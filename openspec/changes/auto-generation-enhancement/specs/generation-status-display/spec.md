# Spec: 生成状态展示

此规范定义详情页如何展示生成任务的状态。

## 新增需求

### 需求: 实时状态显示
详情页必须实时显示所有生成任务的当前状态。

#### 场景: 进入详情页时获取状态
- **当** 用户进入对话详情页
- **那么** 系统必须立即调用 GET /api/conversations/:id/status 获取任务状态
- **并且** 必须显示所有进行中或未完成的任务的状态提示

#### 场景: 轮询更新状态
- **当** 详情页有任务处于 processing 状态
- **那么** 系统必须每隔 2 秒轮询一次任务状态
- **并且** 轮询必须在所有任务完成后停止
- **并且** 轮询间隔不得低于 1 秒以避免服务器压力

### 需求: 状态提示展示
系统必须根据任务状态显示相应的提示信息。

#### 场景: 任务进行中
- **当** AI 摘要任务状态为 processing
- **那么** 系统必须显示"AI 摘要生成中..."提示
- **并且** 提示必须使用加载动画或进度指示器
- **并且** 对应的生成按钮必须禁用

#### 场景: 图片渲染进行中
- **当** 图片渲染任务状态为 processing
- **那么** 系统必须显示"图片渲染中..."提示
- **并且** 必须显示正在渲染的模板名称（Bento UI、Newsletter 或 Retro Letter）

#### 场景: 任务已完成
- **当** 任务状态为 completed
- **那么** 系统必须停止轮询
- **并且** 必须显示生成的结果（摘要、汇总或图片）
- **并且** 必须隐藏进行中的提示
- **并且** 对应的生成按钮必须恢复可用状态

#### 场景: 任务失败
- **当** 任务状态为 failed
- **那么** 系统必须显示错误信息
- **并且** 必须提供"重试"按钮
- **并且** 错误信息必须包含失败原因

### 需求: 结果自动展示
当生成任务完成后，系统必须自动展示生成的结果，无需用户手动刷新。

#### 场景: AI 摘要生成完成
- **当** 社交媒体摘要任务状态从 processing 变为 completed
- **那么** 详情页必须自动显示生成的摘要内容
- **并且** 必须替换掉之前的"生成中"提示

#### 场景: AI 汇总生成完成
- **当** 详细汇总任务状态从 processing 变为 completed
- **那么** 详情页必须自动显示生成的汇总内容
- **并且** 汇总内容必须在"详细汇总"标题下展示

#### 场景: 图片渲染完成
- **当** 图片渲染任务状态从 processing 变为 completed
- **那么** 详情页必须自动在图片展示区域显示渲染的图片
- **并且** 必须使用任务生成的图片 URL 加载图片

### 需求: 多任务并发展示
系统必须能够同时展示多个任务的状态。

#### 场景: 多个任务同时进行
- **当** 同时有 AI 摘要、AI 汇总和图片渲染任务在进行
- **那么** 详情页必须同时显示所有任务的状态
- **并且** 每个任务必须有独立的状态提示
- **并且** 每个任务完成后必须独立更新展示

#### 场景: 部分任务完成
- **当** AI 摘要已完成但图片渲染仍在进行
- **那么** 详情页必须显示完整的 AI 摘要内容
- **并且** 必须继续显示图片渲染的进行中状态
- **并且** 图片完成后必须自动追加到图片展示区域
