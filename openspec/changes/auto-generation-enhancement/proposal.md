# Proposal: 自动生成增强

## 为什么

当前系统存在以下用户体验问题：
1. 采集对话后需要手动点击多个按钮才能生成汇总、摘要和图片，操作繁琐
2. 详情页无法清晰展示生成状态（进行中/已完成），用户不知道当前进度
3. 生成的图片无法在详情页展示，用户无法查看渲染结果
4. 缺少重新生成的能力，无法更新已过期的内容

这些问题导致用户需要多次手动操作，且无法及时获得反馈，降低了系统的易用性和效率。

## 变更内容

### 新增功能

**1. 采集后自动触发生成**
- 采集接口（POST /api/conversations）成功后，自动触发以下任务：
  - AI 社交媒体摘要生成（social_media_summary）
  - AI 详细汇总生成（detailed_summary）
  - 图片渲染（Bento UI 模板）
- 无需用户手动点击，后台自动完成所有生成任务

**2. 详情页状态展示优化**
- 进入详情页时，实时显示各生成任务的状态：
  - 进行中：显示"AI 摘要生成中..."、"图片渲染中..."
  - 已完成：展示生成的摘要、汇总和图片
  - 失败：显示错误信息和重试按钮
- 使用轮询机制实时更新状态

**3. 图片展示功能**
- 详情页新增图片展示区域
- 支持查看所有已渲染的图片（Bento UI、Newsletter、Retro Letter）
- 图片可以点击放大查看

**4. 重新生成能力**
- 详情页保留生成按钮，点击后重新执行生成任务
- 重新生成的内容会覆盖旧数据并落库
- 支持单独重新生成摘要、汇总或图片

### 修改功能

**5. 对话详情展示优化**
- 修改现有的对话详情展示逻辑
- 增加生成状态的显示
- 增加图片的展示

## 功能 (Capabilities)

### 新增功能

- **auto-generation**: 采集后自动触发 AI 生成和图片渲染
- **generation-status-display**: 详情页实时展示生成任务状态
- **image-gallery**: 详情页图片展示和预览功能
- **regeneration**: 重新生成已存在的内容

### 修改功能

- **conversation-detail**: 对话详情页的展示逻辑（增加状态和图片展示）

## 影响

### 后端 API
- 修改 POST /api/conversations：成功后自动触发生成任务
- 新增 GET /api/conversations/:id/status：查询对话的所有生成任务状态
- 修改现有生成接口，支持重新生成（覆盖旧数据）

### 前端
- 修改详情页组件：增加状态展示、图片展示、轮询逻辑
- 新增状态展示组件：显示各任务的状态
- 新增图片展示组件：图片画廊和预览

### 数据库
- 可能需要调整任务状态存储（如果当前实现不支持）

### 性能
- 采集接口响应时间可能增加（因为需要触发生成任务）
- 详情页需要轮询状态，增加 API 调用频率
