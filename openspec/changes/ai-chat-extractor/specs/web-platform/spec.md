# Web Platform Spec

## 新增需求

### 需求:系统必须提供公开展示页
系统必须提供一个公开访问的页面，以瀑布流或列表形式展示已公开的对话记录。展示页必须包含原始对话、AI 生成的总结和分享图片。

#### 场景:访问公开展示页
- **当** 匿名用户访问根路径 `/` 或 `/public`
- **那么** 系统必须显示公开展示页
- **并且** 必须展示所有 `visibility=true` 的对话记录
- **并且** 必须按创建时间倒序排列
- **并且** 必须支持分页或无限滚动加载

#### 场景:瀑布流布局展示
- **当** 用户选择瀑布流视图
- **那么** 系统必须以响应式瀑布流布局展示卡片
- **并且** 每个卡片必须包含：
  - 渲染的分享图（主要视觉）
  - 社媒摘要（简短版）
  - 平台图标和名称
  - 创建日期
  - "查看详情"链接
- **并且** 布局必须在移动端和桌面端自适应

#### 场景:列表布局展示
- **当** 用户选择列表视图
- **那么** 系统必须以垂直列表形式展示记录
- **并且** 每条记录必须包含：
  - 缩略图（分享图）
  - 完整的社媒摘要
  - 来源平台和模型版本
  - 创建时间
  - "展开阅读"按钮
- **并且** 列表必须支持快速浏览和筛选

#### 场景:查看单条记录详情
- **当** 用户点击"查看详情"链接
- **那么** 系统必须跳转到详情页 `/public/:id`
- **并且** 必须显示完整的记录信息：
  - 高清渲染图（可点击放大）
  - 完整的社媒摘要
  - 详细汇总（可折叠）
  - 原始对话（可折叠）
  - 元数据（平台、模型、时间）
- **并且** 必须提供"返回列表"按钮

### 需求:系统必须提供密钥保护的管理后台
系统必须提供一个通过固定密钥 URL 访问的管理后台，无需账户体系。密钥必须是路径的一部分（如 `/admin-secure-path-123`），且可配置。

#### 场景:通过密钥 URL 访问后台
- **当** 用户访问配置的密钥 URL（如 `/admin-secure-path-123`）
- **那么** 系统必须验证路径中的密钥部分
- **并且** 如果密钥正确，必须显示管理后台界面
- **并且** 如果密钥错误，必须返回 HTTP 404（不暴露路径存在）

#### 场景:配置管理后台密钥
- **当** 管理员在配置文件中设置管理路径
- **那么** 系统必须接受完整路径（如 `/admin-secure-path-123`）
- **并且** 必须在应用启动时加载配置
- **并且** 必须确保密钥路径足够复杂（至少 16 个字符）
- **并且** 必须在文档中说明如何配置密钥

#### 场景:管理后台会话管理
- **当** 用户通过密钥 URL 访问后台
- **那么** 系统必须在浏览器中设置会话 Cookie
- **并且** Cookie 必须标记为 HttpOnly 和 Secure
- **并且** Cookie 有效期必须可配置（默认 7 天）
- **并且** 后续访问必须验证 Cookie，无需重复输入密钥

#### 场景:管理后台会话过期
- **当** 管理后台的会话 Cookie 过期
- **那么** 系统必须重定向到密钥 URL
- **并且** 必须显示"会话已过期，请重新访问管理链接"提示
- **并且** 不得自动续期（需要重新通过密钥验证）

### 需求:管理后台必须支持内容状态管理
管理后台必须允许管理员一键切换每条记录的"公开/隐藏"状态。隐藏的记录不得出现在公开展示页。

#### 场景:查看所有记录列表
- **当** 管理员访问管理后台首页
- **那么** 系统必须显示所有对话记录（包括公开和隐藏）
- **并且** 必须在每条记录上显示当前状态（公开/隐藏）
- **并且** 必须使用视觉标识区分状态（如绿色标签=公开，灰色标签=隐藏）
- **并且** 必须按创建时间倒序排列

#### 场景:切换记录可见性
- **当** 管理员点击记录的"公开/隐藏"切换按钮
- **那么** 系统必须立即更新记录的 visibility 字段
- **并且** 必须通过 API 调用后端更新数据
- **并且** 必须在 UI 上显示加载状态
- **并且** 更新成功后必须刷新列表状态
- **并且** 如果切换为"隐藏"，记录必须立即从公开展示页消失

#### 场景:批量切换可见性
- **当** 管理员选中多条记录并点击"批量隐藏"或"批量公开"
- **那么** 系统必须调用批量更新 API
- **并且** 必须显示进度提示（正在更新 X/Y 条记录）
- **并且** 更新完成后必须刷新列表
- **并且** 必须显示操作结果（成功 X 条，失败 Y 条）

#### 场景:筛选记录列表
- **当** 管理员使用筛选功能
- **那么** 系统必须支持按以下条件筛选：
  - 可见性状态（全部/公开/隐藏）
  - 来源平台（Gemini/豆包）
  - 处理状态（已完成/失败）
- **并且** 必须实时更新列表结果
- **并且** 必须在 URL 中保存筛选状态（支持分享筛选链接）

### 需求:管理后台必须支持内容编辑
管理后台必须允许管理员手动修改 AI 生成的总结和摘要。修改后的内容必须保存到数据库，并可选择是否重新渲染分享图。

#### 场景:编辑社媒摘要
- **当** 管理员点击记录的"编辑摘要"按钮
- **那么** 系统必须打开编辑模态框
- **并且** 必须显示当前社媒摘要内容在文本框中
- **并且** 必须支持多行文本输入
- **并且** 必须显示字符计数（限制 280 字）
- **并且** 保存后必须更新数据库

#### 场景:编辑详细汇总
- **当** 管理员点击记录的"编辑汇总"按钮
- **那么** 系统必须打开编辑模态框
- **并且** 必须显示当前详细汇总内容
- **并且** 必须支持富文本编辑（或 Markdown）
- **并且** 保存后必须更新数据库
- **并且** 必须提示"是否需要重新渲染分享图？"

#### 场景:重新渲染分享图
- **当** 管理员编辑内容后选择"重新渲染"
- **那么** 系统必须调用渲染 API
- **并且** 必须显示渲染进度
- **并且** 渲染成功后必须替换旧图片
- **并且** 必须在记录上标记"已手动更新"

#### 场景:取消编辑
- **当** 管理员在编辑模态框中点击"取消"
- **那么** 系统必须关闭模态框
- **并且** 必须不保存任何更改
- **并且** 必须恢复原始内容

### 需求:管理后台必须支持记录删除
管理后台必须允许管理员物理删除对话记录。删除操作必须级联删除关联的总结、渲染图片和数据库记录。

#### 场景:删除单条记录
- **当** 管理员点击记录的"删除"按钮
- **那么** 系统必须显示确认对话框
- **并且** 必须警告"此操作不可撤销"
- **并且** 必须说明将要删除的内容（对话、总结、图片）
- **并且** 确认后必须调用删除 API
- **并且** 删除成功后必须从列表中移除该记录

#### 场景:批量删除记录
- **当** 管理员选中多条记录并点击"批量删除"
- **那么** 系统必须显示批量删除确认对话框
- **并且** 必须显示将要删除的记录数量
- **并且** 确认后必须调用批量删除 API
- **并且** 必须显示删除进度（已删除 X/Y 条）
- **并且** 删除完成后必须刷新列表

#### 场景:删除失败处理
- **当** 删除操作失败（网络错误、服务器错误）
- **那么** 系统必须显示错误提示
- **并且** 必须说明失败原因
- **并且** 记录必须保留在列表中
- **并且** 必须提供"重试"选项

### 需求:系统必须提供搜索和过滤功能
公开展示页和管理后台必须支持按关键词、平台、日期范围搜索和过滤记录，提升内容检索效率。

#### 场景:关键词搜索
- **当** 用户在搜索框输入关键词
- **那么** 系统必须在以下字段中搜索：
  - 社媒摘要
  - 详细汇总
  - 原始对话内容
- **并且** 必须高亮匹配的关键词
- **并且** 必须支持实时搜索（输入时即时更新结果）
- **并且** 必须限制搜索结果数量（如最多 100 条）

#### 场景:按平台过滤
- **当** 用户选择平台筛选器（如"仅显示 Gemini"）
- **那么** 系统必须只显示指定平台的记录
- **并且** 必须在 UI 上显示当前激活的筛选器
- **并且** 必须支持组合筛选（如平台 + 关键词）

#### 场景:按日期范围过滤
- **当** 用户选择日期范围（如"最近 7 天"）
- **那么** 系统必须只显示该时间范围内创建的记录
- **并且** 必须支持自定义日期范围选择
- **并且** 必须在 URL 中保存日期范围参数

### 需求:系统必须支持图片分享和下载
公开展示页必须允许用户下载分享图或分享到社交媒体平台。

#### 场景:下载分享图
- **当** 用户点击"下载图片"按钮
- **那么** 系统必须以原始分辨率下载 PNG 图片
- **并且** 文件名必须包含记录 ID 或主题（如 `ai-chat-123.png`）
- **并且** 不得压缩图片质量
- **并且** 必须在移动端和桌面端都正常工作

#### 场景:分享到社交媒体
- **当** 用户点击"分享"按钮
- **那么** 系统必须显示分享选项（如复制链接、Twitter、微博）
- **并且** 选择平台后必须打开分享弹窗
- **并且** 必须预填充分享文本（社媒摘要）
- **并且** 必须附加分享图片（如果平台支持）

#### 场景:复制分享链接
- **当** 用户选择"复制链接"选项
- **那么** 系统必须将记录详情页的 URL 复制到剪贴板
- **并且** 必须显示"链接已复制"提示
- **并且** 链接必须是永久性的（不受会话过期影响）

### 霟求:系统必须提供响应式设计
Web 平台必须在各种设备上良好显示，包括桌面端、平板和移动设备。

#### 场景:桌面端显示
- **当** 用户使用桌面浏览器（宽度 > 1024px）
- **那么** 瀑布流布局必须显示 3-4 列
- **并且** 管理后台必须使用侧边栏导航
- **并且** 图片必须支持鼠标悬停放大预览

#### 场景:平板显示
- **当** 用户使用平板设备（宽度 768px - 1024px）
- **那么** 瀑布流布局必须显示 2-3 列
- **并且** 管理后台必须使用响应式布局
- **并且** 触摸操作必须流畅

#### 场景:移动端显示
- **当** 用户使用移动设备（宽度 < 768px）
- **那么** 瀑布流布局必须显示 1 列
- **并且** 管理后台必须使用底部导航或汉堡菜单
- **并且** 图片必须支持点击全屏查看
- **并且** 字体和按钮必须适合触摸操作

### 需求:系统必须支持 SEO 优化
公开展示页必须支持搜索引擎优化，包括元标签、结构化数据、友好的 URL。

#### 场景:生成元标签
- **当** 访问单条记录详情页
- **那么** 系统必须在 HTML `<head>` 中包含：
  - `<title>`: 记录标题或社媒摘要前 50 字
  - `<meta name="description">`: 社媒摘要完整内容
  - `<meta name="og:image">`: 分享图片 URL
  - `<meta name="og:title">`: Open Graph 标题
  - `<meta name="og:description">`: Open Graph 描述
- **并且** 元标签必须适合社交媒体分享预览

#### 场景:生成结构化数据
- **当** 访问单条记录详情页
- **那么** 系统必须在页面中包含 JSON-LD 结构化数据
- **并且** 必须使用 Article 或 SocialMediaPosting 类型
- **并且** 必须包含：作者、发布日期、 headline、image、url
- **并且** 必须通过 Google 结构化数据测试工具验证

#### 场景:生成友好 URL
- **当** 系统生成记录详情页 URL
- **那么** URL 必须格式为 `/public/:id` 或 `/public/:slug`
- **并且** 如果使用 slug，必须基于主题生成（如 `/public/ai-chat-about-xxx`）
- **并且** URL 必须简短、易读、不含特殊字符

### 需求:系统必须提供加载状态和错误处理
Web 平台必须在数据加载、API 调用过程中提供明确的加载状态和友好的错误提示。

#### 场景:显示加载状态
- **当** 页面正在加载数据
- **那么** 系统必须显示加载指示器（如骨架屏、旋转图标）
- **并且** 加载指示器必须在内容区域居中显示
- **并且** 加载时间不得超过 3 秒（否则显示提示）

#### 场景:处理网络错误
- **当** API 调用失败（网络错误、超时）
- **那么** 系统必须显示友好的错误提示
- **并且** 必须提供"重试"按钮
- **并且** 不得暴露技术错误详情给终端用户

#### 场景:处理 404 错误
- **当** 用户访问不存在的记录（如 `/public/invalid-id`）
- **那么** 系统必须返回 HTTP 404
- **并且** 必须显示"记录不存在"或"已被删除"提示
- **并且** 必须提供"返回首页"链接

#### 场景:处理服务器错误
- **当** 服务器返回 HTTP 500 错误
- **那么** 系统必须显示"服务器出现问题"提示
- **并且** 必须说明"我们正在修复，请稍后再试"
- **并且** 必须记录错误详情到服务器日志

## 修改需求

无（这是新增功能）

## 移除需求

无
