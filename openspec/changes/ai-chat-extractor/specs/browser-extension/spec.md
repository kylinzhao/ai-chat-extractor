# Browser Extension Spec

## 新增需求

### 需求:插件必须在支持的平台上注入采集按钮
系统必须在 Gemini (Web) 和豆包 (Web) 聊天页面注入可触发的采集按钮。采集按钮必须悬浮在页面显眼位置，或可通过插件 Popup 触发。

#### 场景:在 Gemini 页面注入采集按钮
- **当** 用户访问 Gemini Web 聊天页面
- **那么** 页面必须显示采集按钮
- **并且** 采集按钮必须悬浮在页面右下角或其他显眼位置

#### 场景:在豆包页面注入采集按钮
- **当** 用户访问豆包 Web 聊天页面
- **那么** 页面必须显示采集按钮
- **并且** 采集按钮必须悬浮在页面右下角或其他显眼位置

#### 场景:通过 Popup 触发采集
- **当** 用户点击插件图标打开 Popup
- **那么** Popup 必须显示"采集当前对话"按钮
- **并且** 点击按钮必须触发采集功能

### 需求:插件必须完整抓取对话文本流
系统必须完整抓取 User 与 Assistant 的所有对话内容，保持对话的上下文层级和时序关系。抓取的内容必须包含每条消息的发送者（User/Assistant）、文本内容、时间戳（如果可获取）。

#### 场景:抓取完整对话历史
- **当** 用户点击采集按钮
- **那么** 系统必须抓取当前页面的所有对话消息
- **并且** 必须保持消息的原始顺序
- **并且** 必须标记每条消息的发送者（User 或 Assistant）

#### 场景:处理分段加载的对话
- **当** 对话历史较长需要分段加载
- **那么** 系统必须自动滚动或触发加载机制
- **并且** 必须抓取所有已加载的消息
- **并且** 必须在 UI 上显示加载进度

#### 场景:抓取失败提示
- **当** 抓取过程中发生错误
- **那么** 系统必须向用户显示错误提示
- **并且** 必须说明失败原因（如：页面结构变化、网络问题）

### 需求:插件必须识别并捕获对话中的图片
系统必须识别对话中包含的图片，并保存图片的 URL。如果可能，应当将图片转存或转换为可用格式。

#### 场景:抓取对话中的图片 URL
- **当** 对话消息中包含图片
- **那么** 系统必须提取图片的 URL
- **并且** 必须将 URL 与对应的消息关联
- **并且** 必须标记图片所属的消息位置

#### 场景:处理多个图片
- **当** 单条消息包含多张图片
- **那么** 系统必须抓取所有图片的 URL
- **并且** 必须保持图片的原始顺序

#### 场景:图片 URL 无效
- **当** 图片 URL 无法访问或已过期
- **那么** 系统必须标记该图片为不可用状态
- **并且** 不得中断整个采集流程

### 需求:插件必须自动记录元数据
系统必须自动记录当前平台的名称（Gemini 或 Doubao）、使用的 AI 模型版本、抓取时间戳。元数据必须与对话内容一起发送。

#### 场景:记录 Gemini 平台元数据
- **当** 用户在 Gemini 页面触发采集
- **那么** 系统必须记录平台名称为 "Gemini"
- **并且** 必须尝试获取当前使用的模型版本（如 Gemini Pro/Ultra）
- **并且** 必须记录抓取时间的 ISO 8601 格式时间戳

#### 场景:记录豆包平台元数据
- **当** 用户在豆包页面触发采集
- **那么** 系统必须记录平台名称为 "Doubao"
- **并且** 必须尝试获取当前使用的模型版本
- **并且** 必须记录抓取时间的 ISO 8601 格式时间戳

#### 场景:模型版本不可获取
- **当** 平台未显示模型版本信息
- **那么** 系统必须将模型版本字段设为 "unknown"
- **并且** 必须继续完成采集流程

### 需求:插件必须将数据以 JSON 格式发送至后端 API
系统必须将采集的数据（对话内容、图片 URL、元数据）序列化为 JSON 格式，通过 HTTP POST 请求发送至后端 API。

#### 场景:成功发送数据到后端
- **当** 用户完成采集并点击"发送"按钮（或自动发送）
- **那么** 系统必须将数据序列化为 JSON
- **并且** 必须通过 POST 方法发送至配置的 API 端点
- **并且** 必须设置正确的 Content-Type 头为 "application/json"
- **并且** 必须显示发送成功的提示

#### 场景:网络错误重试
- **当** 发送请求失败（网络错误、超时）
- **那么** 系统必须显示错误提示
- **并且** 必须提供"重试"按钮
- **并且** 点击重试必须重新发送数据

#### 场景:服务器返回错误
- **当** 后端 API 返回 4xx 或 5xx 错误
- **那么** 系统必须显示错误信息
- **并且** 必须显示服务器返回的错误消息（如果有）
- **并且** 不得丢弃已采集的数据（允许用户重试或复制）

#### 场景:请求数据格式
- **当** 构造 POST 请求数据
- **那么** JSON 数据必须包含以下字段：
  - `platform`: 平台名称（Gemini/Doubao）
  - `model_version`: 模型版本
  - `captured_at`: 抓取时间（ISO 8601 格式）
  - `messages`: 消息数组，每个消息包含：
    - `role`: 发送者角色（user/assistant）
    - `content`: 文本内容
    - `images`: 图片 URL 数组（如果有）
    - `timestamp`: 消息时间戳（如果有）

### 需求:插件必须支持后端 API 地址配置
系统必须允许用户配置后端 API 的地址，以便在不同环境（开发、测试、生产）中使用不同的后端服务。

#### 场景:配置 API 地址
- **当** 用户打开插件设置页面
- **那么** 必须提供 API 地址输入框
- **并且** 必须保存配置到本地存储
- **并且** 必须验证输入的 URL 格式合法性

#### 场景:使用默认 API 地址
- **当** 用户未配置自定义 API 地址
- **那么** 系统必须使用预配置的默认 API 地址
- **并且** 默认地址应当在首次安装时提示用户确认

### 需求:插件必须显示采集和发送的实时状态
系统必须在采集和发送过程中向用户提供实时反馈，包括采集进度、发送状态、成功或失败的明确提示。

#### 场景:显示采集进度
- **当** 系统正在抓取对话内容
- **那么** 必须显示"正在采集..."提示
- **并且** 如果对话较长，应当显示已抓取的消息数量

#### 场景:显示发送状态
- **当** 系统正在发送数据到后端
- **那么** 必须显示"正在上传..."提示
- **并且** 应当显示上传进度（如果可获取）

#### 场景:显示成功状态
- **当** 数据成功发送到后端
- **那么** 必须显示"采集成功"的明确提示
- **并且** 提示必须在 3 秒后自动消失
- **或者** 用户可以手动关闭提示

### 需求:插件必须处理跨域和权限问题
系统必须正确处理跨域请求和必要的权限申请，确保在不同网站上的功能正常工作。

#### 场景:申请必要的权限
- **当** 用户首次安装插件
- **那么** 系统必须申请必要的权限：
  - 访问 Gemini 和豆包网站的权限
  - 网络请求权限（用于与后端 API 通信）
- **并且** 必须在安装向导中说明每个权限的用途

#### 场景:处理 CORS 问题
- **当** 后端 API 返回 CORS 错误
- **那么** 系统必须显示友好的错误提示
- **并且** 必须建议用户检查后端 CORS 配置

## 修改需求

无（这是新增功能）

无
